# ① Input Assembler — 입력 조립
	
	- GPU가 렌더링에 사용할 정점(Vertex)과 인덱스(Index) 데이터를 가져오는 단계
	  
	  3D 물체는 일반적으로 삼각형 메시로 구성
	  
	  다음 과정을 통해 지정된 토폴로지와 인덱스 순서로 정점을 처리함
	  
```
Vertices:
0, 1, 2, 3

Triangles:
(0, 2, 1)
(1, 2, 3)
```

**알아야 하는 개념** - Vertex Buffer, Index Buffer, Primitive Topology
# ② Vertex Shader — 정점 셰이더
	
	- 각 정점의 위치를 변환하고 다음 단계로 전달할 속성을 계산하는 것
	
	
               $\boxed{P_{\text{clip}}=P_{\text{proj}}VMP_{\text{local}}}$

- $M$ : Model Matrix - 물체 위치·회전·크기

- $V$ : View Matrix - 카메라 좌표계로 변환

- $P_{\text{proj}}$ : Projection Matrix - 클립 공간으로 변환

	**알아야 하는 개념** -  좌표계, 동차 좌표, 변환 행렬, 법선 벡터

# ③ Tessellation - 테셀레이션
	기존 메시의 삼각형을 GPU가 더 작은 삼각형들로 쪼개는 과정
	- 보통 더 부드럽게 보이거나 변위로 실제 표면 굴곡을 더 세밀하게 만들기 위해 사용함
	- 표면 세분화에 가까움
	

+ 테셀레이션만 하면 삼각형 수만 늘어나고 모양이 안 바뀌어서 변위(Displacement)를 써야함
  
**변위(Displacement)** - 정점들의 위치를 위아래 양옆으로 위치를 바꿈
	바닥이 울퉁불퉁해짐
	지형이 더 자연스러워짐
	돌, 벽, 천 같은 표면이 더 입체적으로 보임
	=> 표면 디테일이 늘어남 

**알아야 하는 개념** - LOD, 정점 보간, 표면 세분화, Displacement

Direct3D에서는 **Hull Shader → Tessellator → Domain Shader**  진행되는데

- **Hull Shader** : “얼마나 쪼갤지” 같은 정보 준비
- **Tessellator** : 실제로 작은 삼각형들로 나눔
- **Domain Shader** : 새로 생긴 점들의 최종 위치 계산
  
# ④ Geometry Shader - 지오메트리 셰이더
	점·선·삼각형 같은 도형을 입력받아 새로운 도형을 생성하거나 변경하는 단계

   **-활용-**
- 삼각형에서 법선 방향으로 선 생성
- 특정한 방식의 도형 확장
- 디버깅용 기하 구조 생성

단 Geometry Shader는 GPU와 플랫폼에 따라 성능상 불리할 수 있고, 최신 렌더링에서는 Compute Shader나 Mesh Shader 같은 다른 방법을 사용하는 경우도 많음

**알아야 하는 개념** - Primitive, 정점 생성, GPU 파이프라인 구조


# ⑤ Primitive Assembly & Clipping — 도형 구성과 클리핑
	정점들을 점·선·삼각형같은 도형으로 구성하고, 카메라에 보이는 범위에 맞게 처리하는 단계
	
**Primitive Assembly(도형 조립)**
- 정점들을 연결해 렌더링할 도형을 구성
  
**Clipping(클리핑)**
- 카메라의 가시 영역 밖에 있는 도형의 일부분을 잘라냄
  
**Culling(컬링)**
- 조건에 따라 도형이나 물체 전체를 렌더링 대상에서 제외
  
# ⑥ Rasterization — 래스터화
	점·선·삼각형 같은 기하 도형이 화면의 어느 픽셀 영역을 차지하는지 판단하고,
	그 영역에 해당하는 프래그먼트(Fragment)를 생성하는 과정
# (1) 왜 래스터화가 필요할까?
![[Pasted image 20261116175337.png]]

왼쪽 삼각형은 정점 3개의 좌표만으로 표현가능.
하지만 오른쪽 화면처럼 그리려면 어떤 픽셀의 위치가 삼각형에 포함되는지 알아내야함

![[Pasted image 20261116175556.png]]

Vertex Shader가 계산한 위치는 이러한 형태

$P_{\text{clip}}=(x_c,y_c,z_c,w_c)$

이걸 원근 나눗셈을 수행함.

$\boxed{ P_{\text{NDC}}= \left( \frac{x_c}{w_c}, \frac{y_c}{w_c}, \frac{z_c}{w_c} \right) }$

이렇게 하면 NDC(Normalized Devicde Coordinates)라는 좌표계로 변환된다

**why? => 원근감을 반영하기 위해**
	멀리 있는 물체는 화면에서 작게 보이고, 가까이 있는 물체는 크게 보이는 현상을 수학적으로 구현할 수 있음.
	그 다음은 Viewport Transform을 통해 NDC좌표를 실제 화면 크기에 대응시킴.
	ex) 해상도가 1920x1080라면 정규화된 좌표를 해당 해상도의 화면 위치로 바꿈
	**#조심해야 될 점**
	- 클리핑이 적절히 이루어진 뒤 원근 나눗셈을 한다는 것, NDC의 깊이 범위 및 화면 Y축 방향은 그래픽스 API에 따라 달라짐
	  

# (2) 어떤 픽셀을 채울까?

삼각형의 세 정점이 다음과 같다고 가정한다

$A = (1, 1), \quad B = (5, 1), \quad  C = (1, 5)$

이 삼각형 내부에 있는 픽셀들을 찾아야 함
삼각형 안에 포함되는지 판단하는 방법 중 하나 => **Edge Function(변 함수)**

![[Pasted image 20261116192052.png]]
**Edge Function의 원리**

정점 A, B와 검사할 점 P를 이용해 값을 계산

$\boxed{ E_{AB}(P)=(B_x-A_x)(P_y-A_y)-(B_y-A_y)(P_x-A_x) }$

**점 P가 방향 있는 선분 ab의 어느 쪽**에 있는지 알려줌

**삼각형의 세 정점에 서로 다른 색상이 저장되어 있다고 가정한다**

![[Pasted image 20261116203431.png]]




$P=\lambda_A A+\lambda_B B+\lambda_C C$

$\lambda_A+\lambda_B+\lambda_C=1$
